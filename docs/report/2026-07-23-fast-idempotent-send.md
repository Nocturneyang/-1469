# 2026-07-23 工作台快速发送与重复提交保护

## 背景

坐席点击发送后，外发任务创建期间输入框反馈较慢。用户再次点击或重复按 Enter 时，前端会生成新的 `client_msg_id`，后端因此把两次操作识别为两条独立外发；第二条随后进入 WhatsApp 单账号限速，表现为重复消息和“超频”。

## 本次改动

- Composer 在发出事件前同步加锁，阻止同一事件循环中的双击和重复 Enter。
- 每次提交由 Composer 生成并携带稳定的 `client_msg_id`；父组件沿用该 ID，不再为重复动作重新生成 ID。
- 点击发送后立即清空可见输入、附件和提及对象，同时保留内存中的待提交快照，让发送操作即时反馈。
- API 创建成功后提交快照；创建失败或响应异常时恢复原文、附件和提及对象。
- 原样重试复用同一个 `client_msg_id`，用于覆盖“服务端已写账本但客户端响应超时”的不确定场景；文本、附件、提及、引用或会话发生变化时生成新 ID。
- typing 状态只在“开始输入/停止输入”发生变化时提交，避免每个字符都重复写入会话动态和渠道动作账本。

## 保持不变的安全边界

- 没有提高 WA 并发，也没有放宽单账号发送间隔、分钟限额或熔断规则。
- 外发仍然遵循 `DB = 账本、文件 = 门铃、定时扫描 = 保险`。
- API 不直接持有 WA client；真实发送仍由对应账号的 runtime worker 串行执行。
- 本次没有使用真实 WA 账号进行测试发送。

## 验证结果

- `npm test`：通过。
- `npm run build`：通过；仅保留现有第三方依赖注释和 bundle 体积警告。
- 隔离数据浏览器验证：对发送按钮执行双击后，输入框立即清空并禁用重复提交，页面只出现一条 pending 消息。
- 隔离 `workbench.sqlite` 验证：唯一测试文本只生成 1 条 `outbound_messages` 记录，状态为 `pending`。
- 浏览器控制台：无错误。
