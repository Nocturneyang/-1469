# 会话消息首屏加载优化

日期：2026-07-14

## 问题

会话列表已经展示未读数和最近消息，但首次点击 WA/TG 会话时，中间消息区需要等待完整消息接口返回。在独立账号库中，接口此前仍复用兼容旧库的通用归一化查询；当账号累计消息较多时，标题和右侧资料已经出现，消息区却长时间空白。

## 调整

- 独立账号库的消息查询改为直接按 `platform + group_id` 读取 `messages`，使用 `idx_messages_group`，仅关联当前账号的 `message_observations` 补充原始元数据。
- 兼容旧版共享库的查询保持不变；优化只应用在工作台自己的独立账号数据目录。
- 群列表响应补充最近消息原生 ID 和方向，供首屏预览使用。
- 首次选择会话时，前端立即把群列表中的最近消息写入内存缓存并展示；消息接口返回后，用完整消息页替换临时预览。
- 加载完整历史期间展示进度条和骨架屏；接口返回空结果时展示明确空状态，不再保留无提示白屏。
- 临时预览没有 `raw_id`，不会提前触发已读上报。

## 渠道范围

WA 和 TG 共用该消息接口及线程组件，因此两者同时支持本次优化。媒体附件仍以真实消息页为准，完整数据返回后继续通过工作台鉴权媒体接口展示。

## 数据边界

本次变更只读取工作台自己的账号级 `raw.sqlite` 和 `workbench.sqlite`，不读取监控项目数据库、session 或 worker 数据。

## 持续加载状态修复

第二轮生产验证发现：首次消息请求尚未返回时，1.5 秒实时轮询会创建新的消息请求代次，使首次响应被判为过期，加载提示可能长期不消失。同时，会话资料和外发账本的读取会用写连接重复执行账号工作库迁移，加重同步阻塞。

修复后：

- 实时刷新复用当前消息请求代次，不再使首次响应失效。
- 首次消息加载期间暂停后台轮询，并在消息请求结束后再加载右侧资料。
- 消息外发账本、会话资料、备注、时间线和入站媒体读取使用只读连接，不执行迁移或默认数据写入。
- 消息接口返回 `Server-Timing`，超过 1 秒时记录不含账号和群 ID 的分段耗时，方便继续定位生产慢查询。
