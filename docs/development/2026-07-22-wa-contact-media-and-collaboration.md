# WA 联系人、媒体与会话协作修复

## 目标

- WA 私聊存在可用联系人名称或消息发送者名称时，不再被同步快照中的电话号码覆盖。
- WA 媒体消息采用与 TG 用户号一致的两阶段入库：先保存媒体类型、文件名、MIME、大小和消息占位，再下载并补齐账号隔离目录中的文件路径。
- 会话状态只按 `platform + account + group_id` 更新，不允许相邻会话或同名会话被前端合并更新。
- 最近动态的在线查看状态按同一会话聚合，展示全部未过期坐席。

## 数据流

WA worker 收到消息后先调用 `whatsappMediaDescriptor` 生成安全的媒体摘要，并立即写入 `raw.sqlite.messages`。页面可以先展示“图片、视频、语音、文件或贴纸”及文件元信息。可下载媒体随后写入该账号的 `media/YYYY-MM/`，第二次幂等更新同一条消息的 `media_path`、大小和哈希。

WA Web 偶尔会在消息事件触发时暂时无法返回媒体正文，因此媒体补偿不能只在账号 `ready` 时执行一次。账号 worker 会周期扫描仍缺少 `media_path` 的最近媒体消息，并通过原生消息 ID 重试下载；下载失败后会先刷新 WhatsApp Web 中的消息模型，再使用更新后的媒体密钥重试。若 `whatsapp-web.js` 的内置 `downloadMedia()` 因 WhatsApp Web 内部 QPL 遥测接口变更而抛出不透明浏览器异常，worker 会改用同一官方下载/解密管理器，并提供前向兼容的无操作 QPL 适配器。该兜底适用于图片、PDF、Office 文件、视频、语音和其他可下载 WA 媒体；不会绕过 WhatsApp 的权限或伪造文件。事件阶段首次下载失败时会缩短下一次补偿间隔。补回文件后 worker 会发送会话更新事件，让已经打开的消息线程自动重新拉取并显示媒体。

账号 supervisor 会把 `starting` 视为可运行状态。WA 浏览器启动和 Web 版本加载超过一次 discovery 间隔时，worker 不会在到达 `ready` 前被错误终止；这保证新消息采集和历史图片/文件补偿都能执行。

下载结果如果被 WA 标记为 `application/octet-stream`，worker 会根据文件头识别 JPEG、PNG、GIF 或 WebP，并修正 MIME 与文件扩展名，避免真实图片被浏览器当成普通附件。已过期且 WA 已无法再次下载的历史媒体仍会保留占位信息，不伪造文件内容。

媒体文件仍只通过鉴权的工作台下载接口读取；SQLite 只保存账号目录内的相对路径，不跨账号或跨项目共享文件。

非图片附件（例如 Word、Excel、PDF、压缩包）在消息卡片中显示明确的“下载”按钮。下载请求仍使用鉴权接口，并由服务端以 `Content-Disposition: attachment` 返回原始文件名；图片继续以内联预览为主。

## 名称优先级

WA 会话名称优先选择非内部 ID、非纯电话号码的群标题、联系人名称或 pushname。API 合并渠道快照与消息列表时，如果快照名称只是电话号码，而最近消息已经保存了真实发送者名称，则使用真实名称。只有 WhatsApp 本身没有任何联系人名称或 pushname 时才保留电话号码。

## Presence 语义

`conversation_presence` 以 `operator_id + platform + account + group_id + mode` 唯一。查看心跳有效期为 90 秒，前端每 45 秒续期。多个坐席打开同一服务账号下的同一会话时，右侧最近动态会列出所有有效查看者；打开同一服务账号下的不同会话不会互相显示。

## 内部备注删除

备注创建者可删除自己创建的备注，具有会话管理权限的坐席可删除该会话下的任意备注。页面删除前必须二次确认；删除后写入 `conversation.note.delete` 操作日志和会话时间线，不在日志中保存备注正文。
