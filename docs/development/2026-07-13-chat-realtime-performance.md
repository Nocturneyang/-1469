# 聊天收发实时性优化

日期：2026-07-13

## 目标

让工作台在不改变“数据库账本、文件门铃、Worker 串行发送、失败熔断”边界的前提下，获得接近常见社媒聊天软件的即时反馈。

## 调整

- 点击发送后先在当前会话即时插入 `pending` 外发消息，不再等待 API 往返后才显示。
- API 成功后用同一个 `client_msg_id` 接管乐观消息，并在后台更新真实外发 ID 与发送状态。
- 当前会话刷新由 5 秒缩短到 1.5 秒；外发待处理期间约 450 毫秒检查一次状态。
- 页面重新获得焦点或从后台恢复时立即增量刷新。
- 会话消息高频刷新与会话列表、右侧协作信息刷新拆开，避免每次轮询都查询全部信息。
- 账号 Worker 监听对应账号的 outbox 文件门铃，门铃到达后立即查询账本并发送；500 毫秒定时扫描继续作为保险。
- 已完成、失败或取消任务的门铃文件会清理，`pending` 文件继续保留到任务被处理。

## 安全边界

- WhatsApp 仍保持单账号串行发送和最小发送间隔，不提高每分钟发送上限。
- 外发事实源仍为账号自己的 `workbench.sqlite`，文件只负责唤醒。
- 渠道 session 仍只由工作台账号 Runtime Worker 持有。
