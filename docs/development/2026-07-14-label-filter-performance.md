# 标签筛选群列表性能优化

日期：2026-07-14

## 问题

选择 WA 标签或 TG 文件夹后，原实现会先聚合所有群，计算每个群的未读、资料、标签、备注和在线状态，最后才按标签过滤。前端也必须等待该请求完成才更新列表。

## 修复

- API 先从 `conversation_service_group_map` 读取标签对应的目标群。
- raw.sqlite 和 workbench.sqlite 查询只读取这些目标群，再计算未读和会话资料。
- 父级工作台标签继续包含其子标签映射。
- 目标群 ID 按 `platform + account` 隔离，不在账号间混用映射。
- 前端缓存已加载的未筛选群列表；标签变更时立即在本地过滤，然后用 API 结果校准。
- 标签变更时立即使旧请求失效，避免慢请求回包短暂覆盖新列表。

## 边界

标签数据仍由对应账号 worker 同步。本次只优化已同步标签的筛选和展示，不让 API 或前端访问 WA/TG session。
