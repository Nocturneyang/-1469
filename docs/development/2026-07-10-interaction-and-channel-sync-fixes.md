# 工作台对话窗口交互与渠道同步修复

日期：2026-07-10

## 修复内容

- 左侧会话列表继续展示星标、状态和跟进提醒，右侧详情移除重复的“会话工作流”编辑区；右侧保留群资料、工作台标签、渠道分组、账号安全和协作信息。
- 会话过滤请求的防抖从 180ms 调整为 80ms，并加入请求序号校验，旧请求不能覆盖最新选择。
- 消息请求按会话序号校验，快速切换会话时不会把上一会话的响应写入当前线程。
- 回复任务写入 `outbound_messages` 后立即恢复输入框，消息和会话列表刷新并行执行。
- 渠道同步按钮支持当前选中的多个平台，提交后后台短轮询刷新标签、工作台分组和会话列表。
- runtime worker 只有在渠道 ready 后才读取同步门铃，避免未 ready 时丢失手动同步请求。
- 渠道快照写入遇到 SQLite 启动竞态锁时会做有限退避重试，避免首轮同步因并发初始化失败。
- WhatsApp 同步在可用时读取原生 labels；Telegram 用户号读取 Dialog Filters，并将当前文件夹物化为 `conversation_service_group_map`。
- 工作台标签入口迁移到消息线程标题右侧；已选工作台标签显示在群名左侧，右侧详情栏不再重复显示标签入口。
- 消息线程按会话和消息筛选条件缓存最近 24 组结果，切换已访问会话时先展示缓存，再后台刷新；单次消息页默认限制为 60 条。

## 边界

渠道 session 仍只由工作台 runtime worker 持有。前端只提交同步请求并读取工作台自己的数据库，不直接访问 WA/TG client。
