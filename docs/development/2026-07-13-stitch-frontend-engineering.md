# Stitch 前端设计稿工程化说明

日期：2026-07-13

## 目标

将 `stitch_innovative_design_project/` 中的 Social Workbench 设计稿落到现有 Vue 3 + Vite + Element Plus 前端中，不另建静态演示项目，不改动工作台 API、独立登录、SQLite 或 runtime worker 边界。

## 设计落地范围

- 以设计稿 `_4` 的三段式 IM 工作面为主：窄导航栏、会话列表、消息线程、会话处理栏。
- 吸收 `_2` 的窄屏处理栏抽屉形态和 `_3` 的工作台标签编辑浮层。
- 保留现有真实数据接线、权限判断、服务账号筛选、渠道标签筛选、消息分页、引用、附件、发送状态、内部备注和最近动态。
- 回复区遵循 MVP 边界，只展示多行文本、附件入口、发送按钮和当前发送账号提示。
- 使用蓝灰色设计系统、紧凑信息密度、1px 分隔线与少量层级色，不引入设计稿中的监控分析或自动化入口。

## 工程约束

- 仅修改 `/Users/a2026/Desktop/工作台/` 内的前端和文档。
- 不复制 Stitch 生成的 Tailwind 单文件代码；将布局、组件状态和响应式规则实现到现有 Vue 组件与共享样式中。
- 桌面端保持三栏；中等宽度将会话处理栏作为覆盖层；窄屏使用会话列表/线程的可用降级布局，避免元素重叠和长文本溢出。
- 沿用现有 Element Plus 图标，避免依赖外部设计稿图片或在线图标字体。

## 验收

- `npm run build`
- `npm test`
- 检查长群名、长账号名、长消息正文和标签的截断/换行。
- 检查 Enter 发送、Shift+Enter 换行、附件入口、失败重试和处理栏收起/展开。
