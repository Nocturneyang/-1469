# 工作台实时与可靠性迭代

日期：2026-07-15

## 目标

本轮只增强工作台的收、发、分派和已读体验：

- 群列表、未读数和当前会话在正常连接下 1 秒内感知变化。
- WhatsApp 外发显示单勾、双勾和蓝色双勾。
- 多坐席认领不会静默覆盖现有归属。
- 切换会话后恢复该会话的文本草稿。
- Worker 重启或发送超时时优先避免重复发送，并保留可审计结果。

本轮不增加 AI、知识库、内容模板、快捷短语、告警侧栏或监控分析能力。

## 外发状态显示

```text
pending / sending  等待或发送中
sent               灰色单勾，渠道 SDK 已返回成功
delivered          灰色双勾，仅渠道有可靠送达回执时展示
read               蓝色双勾，仅渠道有可靠已读回执时展示
failed / dead      发送失败
paused             账号暂停，或发送结果无法可靠判定
canceled           坐席取消
```

WhatsApp ACK 映射：

- ACK 1：保持或升级为 `sent`。
- ACK 2：升级为 `delivered`。
- ACK 3、4：升级为 `read`。

状态只能单向升级，不得因重复或乱序 ACK 从 `read` 降为 `delivered`。Telegram 没有可靠回执时以 `sent` 为最终成功状态，不伪造双勾。

## 实时通知

- 全局 SSE 只发送轻量事件，不发送完整消息正文。
- 浏览器收到事件后按现有权限接口重新读取群列表或当前会话。
- SSE 断开时自动重连，低频轮询继续作为保险。
- 声音和桌面通知由坐席主动开启；页面标题显示未读总数。
- 桌面通知默认只显示群名和“收到新消息”，避免锁屏泄露正文。

## 草稿

- 草稿键包含当前坐席、平台、服务账号和群 ID。
- 第一版只持久化文本，不把 Base64 附件写入 `localStorage`。
- 发送成功后清除该会话草稿；发送创建失败时保留草稿。

## 分派

- “认领”仅在会话没有 active 归属时成功，否则返回 `409 Conflict`。
- 重复认领给当前坐席可按幂等成功处理。
- 移交他人和释放他人归属需要管理能力；普通坐席只能释放自己的归属。
- 后端约束和权限校验必须独立于前端是否展示入口。

## 发布边界

- 不使用生产 WA/TG 账号做自动化外发测试。
- 不修改生产账号的 `send_enabled`。
- 保留全局发送开关、账号发送开关、单账号串行、限速和熔断。
- 先完成本地自动化和浏览器验证，再通过独立部署工作树发布。
