# WA Web 体验对齐：P0–P2 迭代

## 目标

让坐席在工作台完成高频 WA 操作时接近 WhatsApp Web，同时保留工作台独有的权限、分派、内部备注和审计。体验接近不等于浏览器直接驱动 WA：账号 runtime worker 始终是唯一渠道执行者。

## 已实施

### P0：可信状态与连续性

- 引用回复只接受已验证的 `native_message_id`；不能定位时 API 返回冲突错误，不会把“引用回复”悄悄降级为普通消息。
- 工作台已读与 WA 原生已读分离。滚动阅读仅更新坐席作业进度；“标记 WA 已读”显式进入原生动作队列。
- 原生动作使用 `channel_action_tasks`、账号隔离门铃、worker 定时扫描与可恢复 lease。
- 会话列表继续以本地缓存先渲染、后台刷新；渠道快照是最终原生状态来源。
- `message_create` 与 `message` 使用同一原生 ID 去重；ready、重连后的历史消息由账号 worker 分批校准到本地镜像，坐席打开会话不会直接请求 WA。

### P1：高频会话互动

- 已接收的 WA 原生回应继续聚合展示；坐席可对具有原生消息 ID 的消息发送 emoji 回应。
- 回复框的输入状态可向 WA 请求“正在输入/停止输入”，并带短时过期保护。
- 群会话快照同步群简介、成员原生 ID、显示名与管理员身份。回复框从该账号、该会话的快照中选择成员；API 再校验成员仍属于会话，worker 才把已验证的联系人作为 WA `mentions` 发送。`@显示名` 本身从不被当成原生提及事实。
- 消息线程补充语音播放、视频播放和位置跳转；图片、文件、贴纸沿统一媒体落盘与授权读取链路。

### P2：受控原生操作

- 有管理权限的坐席可请求 WA 会话归档、置顶、静音、标记未读及相反操作。
- 本账号已确认发送、且仍可由 WA 定位的消息可请求编辑或撤回。
- 每个请求均写入坐席审计和会话动态；页面只展示任务已提交，worker 成功/失败才是执行事实。

## 刻意不做

- 不修改 WA 原生标签；标签仍为同步读取与筛选用途。
- 不做通话、投票、计划活动。
- 不承诺群内逐成员已读；仅展示渠道可可靠提供的聚合 ACK。
- 不在 API、浏览器或测试脚本中持有 WA session。

## 验收场景

1. 对一条存在 `native_message_id` 的入站消息引用回复，账本中的 `quote_msg_id` 为该原生 ID。
2. 目标消息没有原生 ID 时，引用、回应、编辑、撤回请求返回明确错误且不创建伪任务。
3. 重复提交相同 `client_action_id` 只生成一条动作任务。
4. worker 重启后，未完成的动作 lease 可恢复；过期输入中任务不再发送。
5. WA 账号未 ready 时任务保持可观察的 pending/failed 状态，浏览器不显示“已成功”。
6. 提及成员时，账本保存的是成员原生 ID；快照缺失或成员不属于该群时 API 返回冲突错误，不能把文字 `@名字` 伪装成渠道原生提及。
