# 统一门户与权限体系

## 功能目标

在同一生产域名下统一管理监控系统、客服工作台和管理后台的登录入口、角色权限和数据范围。系统必须承认监控系统与工作台共享 `database.sqlite` 原始采集底座，但业务权限按模块和动作隔离。

## 用户故事

- 作为 SSO 用户，我登录后只看到自己被授权的入口：监控系统、客服工作台或管理后台。
- 作为超级管理员，我可以维护角色、权限项、授权对象、入口权限和工作台服务账号/分组范围。
- 作为监控只读用户，我可以查看看板和知识资产，但不能修改配置、账号或审核资产。
- 作为客服坐席，我只能查看和回复授权服务账号、授权分组内的会话。

## 验收标准

- `/login` 公开；`/entry` 根据 `portal_access` 展示可进入模块。
- `/api/workbench/*` 必须在登录后校验 `can_workbench`，再按服务账号和分组校验 `can_view/can_reply/can_assign/can_manage`。
- 监控 API 必须在登录后校验 `can_monitor`，配置、账号、日志、资产写操作再校验具体权限项。
- `/api/admin/access-control/*` 必须要求 `admin:access:manage`。
- 本地旧 `admin` 与工作台超级管理员保持兼容，自动具备超级管理员等效权限。
- `database.sqlite` 仍只作为共享原始事实层，不被权限系统写入。

## 数据边界

- `database.sqlite`：采集 worker 写入，监控系统和工作台按权限只读。
- `workbench.sqlite`：统一角色、权限项、入口权限、工作台范围和工作台作业账本。
- `analytics.sqlite`：分析输出库，不作为权限事实源。
