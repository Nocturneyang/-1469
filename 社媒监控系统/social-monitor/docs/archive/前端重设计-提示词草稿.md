# Lovart 前端重新设计提示词

## 项目背景

我有一个社交媒体监控系统（Social Monitor），已经完成了前后端分离重构。现在希望使用 Lovart 对前端进行重新设计，提升用户体验和视觉效果。

## 当前技术栈

- **前端框架**: Vue 3 (Composition API)
- **构建工具**: Vite
- **UI 组件库**: Element Plus
- **状态管理**: Pinia
- **路由**: Vue Router
- **HTTP 客户端**: Axios
- **图标库**: @element-plus/icons-vue

## 当前设计风格分析

### 色彩系统
```css
--bg: #f4f7f9;              /* 主背景色 */
--bg-gradient: #ffffff;     /* 渐变背景 */
--t: #2d3748;               /* 主文本色 */
--t2: #4a5568;              /* 次要文本色 */
--t3: #718096;              /* 辅助文本色 */
--p: #6b46c1;               /* 主色调（紫色） */
--p-light: #9f7aea;         /* 主色调浅色 */
--wa-green: #25D366;        /* WhatsApp 绿色 */
--tg-blue: #0088cc;         /* Telegram 蓝色 */
```

### 设计特点
- **圆角设计**: 大量使用 24px 和 14px 圆角
- **卡片式布局**: 使用白色卡片 + 柔和阴影
- **emoji 图标**: 广泛使用 emoji 作为视觉标识
- **柔和阴影**: 使用多层阴影营造层次感
- **悬浮效果**: hover 时有轻微上浮和阴影加深
- **渐变动画**: 加载状态使用脉冲动画

### 页面结构
1. **登录页** (Login.vue)
2. **主布局** (Layout.vue) - 侧边栏 + 顶栏 + 内容区
3. **首页/仪表盘** (Home.vue) - 4 个统计卡片
4. **消息流** (Feed.vue) - 消息卡片列表 + 平台筛选
5. **知识库** (KnowledgeBase.vue) - QA 知识库管理
6. **供应商画像** (SupplierProfiles.vue) - 供应商评分和告警
7. **设备知识库** (DeviceKB.vue) - 设备信息管理
8. **内容模板** (ContentTemplates.vue) - 内容模板库
9. **账号管理** (Admin.vue) - 账号卡片网格
10. **系统配置** (AdminConfig.vue) - 多个配置模块

## 设计目标

### 期望改进方向
1. **现代化视觉**: 采用更现代的设计语言，可能参考 Material Design 3、Apple Human Interface Guidelines 或其他现代设计系统
2. **更好的信息层次**: 优化信息架构，让重要信息更突出
3. **提升交互体验**: 改善用户交互流程，增加微交互和过渡动画
4. **统一设计语言**: 确保所有页面遵循一致的设计规范
5. **响应式优化**: 更好的移动端适配
6. **无障碍设计**: 提升可访问性

### 需要保持的核心要素
1. **功能完整性**: 所有现有功能必须保持不变
2. **数据流不变**: API 接口和数据结构不改变
3. **核心交互**: 主要的用户操作流程保持一致
4. **品牌识别**: 如果有品牌色彩，需要保留品牌识别度
5. **性能**: 不影响页面加载和交互性能

## 具体设计要求

### 1. 色彩系统重构
- 建议采用更现代的色彩系统
- 考虑深色模式支持
- 保持足够的对比度确保可读性
- 为不同状态（成功、警告、错误、信息）定义明确的色彩

### 2. 排版系统
- 建立清晰的字体层级（H1-H6, body, caption 等）
- 优化行高和字间距
- 考虑中英文混排的显示效果
- 建立一致的字号系统

### 3. 组件设计
- **按钮**: 设计多种按钮样式（主要、次要、文字按钮、危险按钮等）
- **卡片**: 重新设计卡片样式，考虑不同内容的卡片变体
- **表单**: 优化输入框、选择器、开关等表单控件
- **表格**: 改进表格设计，增加排序、筛选等功能
- **导航**: 优化侧边栏和顶部导航的设计
- **弹窗**: 重新设计对话框和抽屉组件

### 4. 图标系统
- 考虑替换 emoji 为更专业的图标库（如 Lucide、Heroicons）
- 或保持 emoji 但优化使用方式
- 建立一致的图标使用规范

### 5. 动画和过渡
- 添加页面切换动画
- 优化组件加载和卸载的过渡效果
- 添加微交互（按钮点击、卡片悬浮等）
- 保持动画流畅，不影响性能

### 6. 响应式设计
- 优化移动端布局
- 考虑平板设备的适配
- 确保在不同屏幕尺寸下的可用性

### 7. 暗色模式
- 考虑添加暗色模式支持
- 确保暗色模式下的可读性
- 提供主题切换功能

## 技术实现建议

### 设计系统工具
- 考虑使用 Tailwind CSS 进行样式管理
- 或继续使用 CSS 变量但进行系统化重构
- 可以考虑使用 Figma 进行设计稿制作

### 组件库选择
- 可以继续使用 Element Plus，但进行深度定制
- 或考虑迁移到其他组件库（如 Ant Design Vue、Naive UI）
- 或基于 Headless UI 构建自定义组件

### 图标方案
- 推荐使用 Lucide Vue（轻量、现代）
- 或 Heroicons（与 Tailwind 配合良好）
- 或继续使用 Element Plus 图标库

## 设计交付物

1. **设计规范文档**: 包括色彩、排版、间距、组件等规范
2. **设计稿**: 主要页面的高保真设计稿（Figma/Sketch）
3. **组件库**: 可复用的 UI 组件
4. **样式系统**: 重构后的 CSS/样式代码
5. **实施指南**: 如何将新设计应用到现有代码的指导

## 约束条件

1. **向后兼容**: 确保不破坏现有功能
2. **渐进式迁移**: 可以分阶段进行，不需要一次性重写所有页面
3. **性能优先**: 设计不能影响页面性能
4. **可维护性**: 代码结构清晰，便于后续维护
5. **团队协作**: 考虑团队的开发习惯和能力
