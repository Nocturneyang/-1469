# 完整认证系统实现计划

实现基于 admin 和 view 双角色的认证系统，登录界面提供管理员登录和游客登录选项，admin 具有增删改查配置权限，view 只有只读权限。

## 需求分析

**角色定义：**
- **admin**: 需要用户名密码登录，具有增删改查配置权限，可访问所有页面
- **view**: 需要登录（游客登录），只有只读权限，可访问除配置管理外的其他页面

**权限控制：**
- `/admin/accounts` 和 `/admin/config` 仅 admin 可访问
- 其他页面（Dashboard、Analytics、Feed、KnowledgeBase等）view 可访问
- view 角色对配置相关页面只读，不能修改

## 实现方案

### 1. 后端改造

#### 1.1 扩展 auth 路由 (`routes/auth.js`)
- 添加 `/api/auth/view-login` 接口，游客登录（无需密码）
- 添加用户管理接口：
  - `POST /api/auth/users` - 创建用户（仅 admin）
  - `PUT /api/auth/users/:id/password` - 修改密码（仅 admin）
  - `PUT /api/auth/users/:id/role` - 修改角色（仅 admin）
  - `DELETE /api/auth/users/:id` - 删除用户（仅 admin）
  - `GET /api/auth/users` - 获取用户列表（仅 admin）

#### 1.2 数据库扩展
- users 表已存在，无需修改结构
- 确保有默认的 admin 用户（admin/admin123）
- 添加默认的 view 用户（view/view 或无需密码）

#### 1.3 修改认证中间件 (`middleware/auth.js`)
- 保持现有 JWT 验证逻辑
- admin 和 view 都需要有效的 JWT token

### 2. 前端改造

#### 2.1 修改登录页面 (`views/Login.vue`)
- 添加管理员登录和游客登录的选项卡或按钮
- 管理员登录：需要用户名和密码
- 游客登录：点击即可登录，无需输入凭据
- 显示角色权限说明

#### 2.2 修改路由守卫 (`router/index.js`)
- 区分 admin 和 view 角色的访问权限
- `/admin/accounts` 和 `/admin/config` 需要 admin 角色
- 其他页面允许 view 角色访问
- 根据用户角色控制路由访问

#### 2.3 创建用户管理组件
- 创建 `frontend/src/views/UserManagement.vue`
- 实现用户列表展示
- 实现创建用户、修改密码、修改角色、删除用户功能
- 添加到 Admin 页面的路由中

#### 2.4 修改认证 Store (`store/auth.js`)
- 添加游客登录逻辑
- 区分 admin 和 view 的登录状态

#### 2.5 修改 Layout 组件
- 在导航栏中显示当前用户角色
- admin 角色显示用户管理入口
- view 角色隐藏管理功能
- view 角色访问配置页面时显示只读提示

### 3. 实现步骤

**后端步骤：**
1. 扩展 `routes/auth.js`，添加游客登录接口和用户管理接口
2. 更新数据库，添加默认 view 用户
3. 测试后端认证逻辑

**前端步骤：**
1. 修改 `views/Login.vue`，添加管理员登录和游客登录选项
2. 修改 `router/index.js`，实现角色权限控制
3. 修改 `store/auth.js`，添加游客登录逻辑
4. 创建 `UserManagement.vue` 组件
5. 修改 `Layout.vue`，添加用户管理入口和角色显示
6. 修改 `AdminConfig.vue`，view 角色只读模式
7. 测试前端权限控制

**测试步骤：**
1. 测试 admin 登录和权限控制
2. 测试 view 游客登录和只读权限
3. 测试用户管理功能
4. 测试页面访问权限

## 注意事项

1. 游客登录需要确保安全性，可以考虑 IP 白名单等额外措施
2. 用户管理功能需要严格的权限控制，只有 admin 可操作
3. 密码修改需要验证原密码（修改自己密码时）
4. 删除用户时需要确认，不能删除自己
5. Token 过期时间需要合理设置
6. view 角色访问配置页面时，所有表单和按钮应禁用或隐藏
