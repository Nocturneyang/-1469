# 2026-07-01 生产页面加载和板块切换性能修复

## 背景

生产域名首屏加载和板块切换存在明显延迟。排查发现首屏主 JS/CSS 体积较大且生产响应未使用 gzip/brotli；部分情报和画像接口在请求内同步读取大量 SQLite 数据并做内存聚合，重复切换板块时容易阻塞 API 进程。

## 本次变更

- 前端构建后生成 `.br` 和 `.gz` 预压缩静态资源。
- Express 静态服务根据 `Accept-Encoding` 优先返回预压缩文件，并补充 `Vary`、`CDN-Cache-Control`、`Surrogate-Control` 等缓存头。
- 前端入口改为按需注册 Element Plus 基础组件，移除全量图标全局注册。
- Vite 增加 vendor/manual chunks，拆分 Vue、Element Plus、图标和 HTTP 依赖。
- 后端增加慢 API 日志，默认记录超过 1200ms 的 `/api/*` 请求。
- 知识资产池、区域业务信号、正式资产投影和供应商覆盖聚合增加更长的内存缓存窗口，降低重复切换板块时的同步扫库成本。
- 区域/专项情报 AI 默认超时从 25s 降到 12s，前端 AI 补充请求超时从 60s 降到 30s。

## 追加修复

- `region-dashboard` 增加基础仪表盘短缓存，避免区域运营情报和业务域口径来回切换时重复同步扫库。
- 区域情报消息扫描默认限制为 9000 条、资产池默认限制为 3500 条，并支持通过环境变量调整。
- 区域/板块筛选下推到资产池和消息信号查询前置阶段，减少先取全量再在内存过滤的成本。
- 区域情报页面首次加载设置 12s 超时；已有数据时切换筛选不清空旧热力图，只显示轻量刷新提示。

## 日快照策略

- 资产分析相关 GET 数据默认按上海时间（UTC+8）自然日生成快照，同一天相同参数请求直接返回快照。
- 快照持久化到 `DATA_DIR/cache/asset-analysis-snapshots/{YYYY-MM-DD}/`，Pod 重启后仍复用当天结果。
- 服务启动后会后台预热常用默认板块；之后每天上海时间 00:01 清空内存并预热新一天快照。
- 影响范围包括资产发现、区域运营情报、客服运营情报、设备技术情报、实体关系图谱、QA 知识库、设备知识库、内容模板库、供应商画像等资产分析页面。
- 可通过 `ASSET_DAILY_SNAPSHOT_DISABLED=1` 临时关闭日快照；可通过 `ASSET_DAILY_SNAPSHOT_WARMUP_DISABLED=1` 关闭后台预热。

## 影响范围

- 影响前端首屏静态资源传输、生产静态缓存头、区域/专项情报、实体图谱、供应商画像和正式资产投影类接口。
- 资产审核、晋升、使用反馈和联系人打标仍会清空分析性能缓存，避免人工操作后长期看到旧结果。
- 缓存窗口内可能存在最多数分钟的数据展示延迟，适用于运营看板类页面；原始采集写入和分析器行为不变。

## 验证建议

- 运行 `npm run build`，确认 `frontend/dist/assets` 中生成 `.br` 和 `.gz` 文件。
- 运行 `npm test` 验证既有阶段测试。
- 部署后检查生产 `/assets/*.js` 响应头是否包含 `Content-Encoding: br` 或 `gzip`，并确认 `Cache-Control` 不再被 CDN 覆盖为 `no-cache`。
