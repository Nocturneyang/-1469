# 开发问题记录与避坑指南 (Lessons Learned)

本文档用于记录项目开发过程中出现的典型问题、产生原因以及标准的规避方案，防止后续开发中再次犯同样的错误。

## 1. 列表操作（如编辑）导致表单字段显示 `undefined`
- **问题描述**：
  在拼接前端列表的 HTML 时，点击“编辑”按钮打开弹窗，结果弹窗内输入框的内容全部显示为 `undefined`。
- **产生原因**：
  - 在模板字符串 (` ` `) 中直接给 `onclick` 传入了错误的参数。例如，原本函数期望接收一个 Object，但传入了字符串类型的 `id`，导致访问 `editData.region` 时拿不到属性，返回 `undefined`。
  - 数据赋值给 DOM 节点时缺少兜底。
- **规避方法**：
  1. **禁止在 HTML 中直接传对象**：`onclick` 中只能传递唯一标识符（如 `id` 或 `account`）。例如 `<button onclick="editItem('${item.id}')">`。
  2. **增加数据中转层**：编写对应的中转函数（如 `editItem(id)`），在该函数内部通过 ID 从全局缓存（如 `window.allData`）中找出完整的 Object，再将其传递给弹窗渲染函数。
  3. **赋值必须兜底**：在给 input 赋值时，一律使用 `data.field || ''` 来避免 null 变成字面量 `"null"` 或是 `undefined`。

## 2. 修改函数名导致 UI 按钮点击失效（无反应）
- **问题描述**：
  在重构或新增逻辑时，顺手修改了 JS 函数名称（例如将 `submitRegion` 改为了 `saveRegionConfig`），但在前端点击相应的保存按钮时，毫无反应（控制台静默报错）。
- **产生原因**：
  只改了 JS 里的函数名和定义，忽略了 HTML 里写死的事件绑定（如 `<button onclick="submitRegion()">`），导致点击时寻找不到目标函数。
- **规避方法**：
  1. **改名必搜索**：在更改任何作为交互入口的 JS 函数名称前，必须全局 `grep` / 搜索整个文件或项目，确保对应的 HTML `onclick="..."` 能够同步被修改。
  2. **优先保持原名**：如果是为了扩展现有按钮的功能，尽量保留原有绑定的函数入口名称，并在其内部调用新增加的逻辑函数。

## 3. 数据库新增字段导致的插入失败（SQL Error）
- **问题描述**：
  在 SQLite 增加新表字段（例如 `business_sector`）后，部分逻辑保存时报错或者新字段写入失败。
- **产生原因**：
  在 Schema 文件增加了字段，也改了某个主流程下的 `INSERT` 语句，但遗漏了其他分支逻辑或辅助模块（比如各个 analyzers 分析器）里面针对同一张表的 `INSERT INTO` 语句。
- **规避方法**：
  1. **全局替换**：每当在数据库中新增字段，务必全局搜索 `INSERT INTO 表名` 和对应的 `UPDATE 表名`，检查所有可能写入该表的地方。
  2. **参数对齐**：确保 `INSERT INTO (..., 新字段)` 和 `VALUES (..., ?)` 中的数量严格一一对应。
  3. **空值兜底**：组装插入参数时，如果数据源中不一定包含该字段，必须使用 `|| null` 或 `|| ''` 进行兜底，防止出现 `undefined` 导致程序异常。

## 4. 钉钉机器人日报推送的格式与逻辑问题
- **问题描述**：
  - **重复推送**：同一个群组在日报中出现多次，或同一个机器人账号连续收到多条类似的推送消息。
  - **视觉疲劳**：Markdown 格式拥挤，缺乏层次感，出现不明意义的竖线（引用块干扰），AI 生成的冗余图标（Emoji）干扰阅读。
  - **推送失败**：日志报错“关键词不匹配”或“token is not exist”。
- **产生原因**：
  - **循环维度错误**：原代码按“平台”循环推送，而不同平台可能共享同一个 Webhook URL，导致重复触发。
  - **Markdown 渲染特性**：钉钉对 Markdown 的支持有限，单行换行会被合并，且过度使用引用块（`>`）会产生竖线。
  - **AI 噪音**：LLM 生成摘要时倾向于带入各种 Emoji 图标，且在无关键信息时返回“无”、“运营正常”等占位符。
- **规避方法**：
  1. **Webhook 聚合推送**：**必须以 Webhook URL 为唯一键进行数据聚合**。发送前应汇总所有摘要，再按 URL 分组，确保一个机器人只发一次消息。
  2. **增强留白与层次**：
     - **使用双换行**：在模块标题（如 `**【📌 关键讨论】**`）和群组标题前后使用双换行符，强制钉钉分段。
     - **去引用化**：避免使用 `>` 引用块。使用 `###` 标题和 `-` 列表项构建扁平化的视觉层级，并辅以 `---` 水平分割线。
  3. **内容清洗机制**：
     - **正则剔除 Emoji**：增加正则过滤（如 `replace(/[ὠ0-ὤF...]/g, '')`），彻底消除内容区自带的图标噪音。
     - **过滤无效摘要**：通过黑名单剔除“无”、“运营正常”、“无异常”、“—”等无实际意义的 AI 占位符。
  4. **配置双重检查**：
     - **关键词对齐**：确保推送标题/正文包含机器人设置的“自定义关键词”（如“日报”、“汇总”）。
     - **PM2 及时重启**：后端代码修改后，**必须重启对应的 PM2 进程**才能生效。
